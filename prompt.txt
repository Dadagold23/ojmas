# MODULE 1 — MANUSCRIPT INGESTION AND APA 7 FORMATTING ENGINE

## 1.1 Objective

Build a manuscript-processing service that accepts a submitted document, identifies its structure, applies supported APA 7 formatting rules, and produces a formatted manuscript with a transparent validation report.

Prioritize Microsoft Word DOCX input and DOCX output. PDF may be supported for text extraction or reference purposes, but must not be treated as equivalent to an editable source document.

## 1.2 Document ingestion

Implement:

- Secure DOCX upload.
- File-type, file-size, and content validation.
- Protection against malicious uploads and archive-based attacks.
- Private storage of the original manuscript.
- Preservation of the original file and its checksum.
- Processing status and error reporting.
- Safe extraction of document structure.
- Clear handling of scanned PDFs, unsupported documents, and corrupted files.

Never overwrite the original submission during formatting.

## 1.3 Structural recognition

Where supported by the source document, identify:

- Manuscript title.
- Author names and affiliations.
- Corresponding-author information.
- Abstract and keywords.
- Main body sections and heading levels.
- In-text citations.
- Reference list.
- Tables and table notes.
- Figures, captions, and alternative text where available.
- Footnotes and endnotes.
- Appendices.
- Equations and mathematical notation.
- Acknowledgments, funding statements, and conflict-of-interest declarations.
- Data availability and other relevant research declarations.

Do not silently discard content that the parser cannot recognize. Flag unsupported or uncertain elements for review.

## 1.4 APA 7 formatting rules

Implement a versioned, testable rule set for applicable APA 7 requirements, including:

- Page dimensions and margins.
- Approved font choices and sizes.
- Line spacing and paragraph indentation.
- Page numbering.
- Title-page layout.
- Heading levels.
- Paragraph formatting.
- In-text citation presentation.
- Reference-list formatting and hanging indentation.
- DOI and URL presentation.
- Table and figure numbering, titles, notes, and placement.
- Appendix presentation.
- Appropriate capitalization, italics, punctuation, and spacing.

Distinguish between APA 7 student-paper conventions, professional-paper conventions, and journal-specific submission requirements.

Configure the correct manuscript profile for OJMAS rather than blindly imposing student-paper rules on every journal submission.

Maintain a separate configurable OJMAS style profile for any journal-specific requirements that differ from APA 7.

## 1.5 Citation and reference validation

Build a validation service that can:

- Identify citations without corresponding reference entries.
- Identify reference entries that appear uncited.
- Detect inconsistent author names and publication years.
- Flag incomplete bibliographic details.
- Identify potentially duplicated references.
- Detect malformed DOI and URL entries.
- Identify citation patterns that require manual examination.

Where a trusted bibliographic service is available and authorized, allow external metadata verification.

Never invent missing authors, titles, publication dates, DOIs, page ranges, or publication details. Distinguish verified metadata from unverified suggestions.

Do not claim that a citation supports a research statement merely because its reference exists.

## 1.6 Validation report and preview

Generate a report containing:

- Formatting issues corrected automatically.
- Issues that require author intervention.
- Bibliographic information that could not be verified.
- Content that could not be safely converted.
- Warnings about possible layout changes.
- Processing errors, if any.

Provide a preview of the formatted manuscript and allow the author to download the formatted DOCX.

Require the author to inspect and approve the formatted submission before it proceeds into the editorial workflow, unless the existing journal policy explicitly provides another approved procedure.

## 1.7 Module 1 acceptance criteria

- The original document remains unchanged.
- The formatted DOCX opens successfully in compatible word processors.
- Tables, images, equations, references, and headings are preserved or explicitly flagged.
- Formatting rules are tested against representative sample documents.
- Validation reports accurately distinguish errors from warnings.
- Unsupported content is not silently deleted.
- No manuscript is automatically accepted or rejected based solely on formatting results.

Stop after delivering the implementation, test results, known limitations, and demonstration. Wait for my approval.

# MODULE 2 — INTEGRATED BROWSER-BASED MANUSCRIPT WORKSPACE

## 2.1 Objective

Implement an in-browser editorial workspace that enables authorized users to inspect, edit, comment on, and manage manuscripts without routinely downloading files to their computers.

Evaluate established technologies such as CKEditor 5, Tiptap, and ONLYOFFICE Docs against the project's actual requirements.

Before choosing a technology, verify:

- DOCX import and export fidelity.
- Support for tracked changes.
- Contextual comments and annotations.
- Version history.
- Concurrent editing, if required.
- Tables, equations, figures, footnotes, and references.
- Self-hosting compatibility.
- Licensing and commercial-use restrictions.
- Resource requirements and hosting compatibility.
- Integration with Laravel authentication and authorization.

Do not install multiple competing editors. Present your recommendation and wait for approval if the choice introduces significant costs, external services, or infrastructure requirements.

## 2.2 Workspace interface

Create a professional, responsive workspace containing:

- Manuscript title and unique submission identifier.
- Current editorial stage and document version.
- Main document editing area.
- Contextual comment panel.
- Revision and change-tracking controls.
- Version-history panel.
- Save status and processing indicators.
- Editorial instructions and relevant deadlines.
- Authorized actions for the current role.

Provide autosave where reliable, visible save confirmation, recovery from failed requests, and protection against accidental data loss.

Autosave must not overwrite newer edits from another user without detecting and resolving the conflict.

## 2.3 Collaborative editing

Implement the capabilities supported by the selected editor:

- Edit authorized manuscript content in the browser.
- Add comments to selected text.
- Reply to comments.
- Resolve and reopen comments.
- Record insertions and deletions.
- Review and accept or reject tracked changes where authorized.
- Compare manuscript versions.
- Restore an authorized previous version.
- Preserve author revisions and editorial annotations.

Where the chosen editor cannot provide native collaborative editing or reliable track changes, implement a tested alternative or clearly document the limitation. Do not claim real-time collaboration if the application only supports sequential editing.

## 2.4 Document export

Support exporting the manuscript to DOCX with appropriate preservation of:

- Paragraphs and headings.
- Citations and references.
- Tables and figures.
- Captions and notes.
- Track changes and comments where the selected format and editor support them.

Generate publication PDFs separately from the approved manuscript using the journal's production pipeline. Do not assume DomPDF can faithfully convert arbitrary DOCX documents; select and test a suitable conversion method.

## 2.5 Module 2 acceptance criteria

- Authorized users can open manuscripts in the browser.
- Editing and saving persist reliably.
- Comments remain associated with the correct manuscript and text where supported.
- Version history records meaningful changes.
- Concurrent edits do not silently destroy another user's work.
- DOCX import and export are tested with representative complex documents.
- Unauthorized users cannot access or modify protected manuscripts.

Stop and wait for my approval.

# MODULE 3 — ROLE-BASED EDITORIAL WORKSPACE

## 3.1 Author permissions

Authors must be able to:

- View their own submissions and permitted editorial feedback.
- Inspect formatting and validation reports.
- Respond to revision requests.
- Edit and resubmit manuscripts when a revision window is open.
- View revision deadlines and submission status.
- Compare their submitted and revised versions.
- Download their own permitted manuscript files.

Authors must not be able to alter reviewer reports, editorial decisions, confidential notes, or the audit trail.

## 3.2 Reviewer permissions

Reviewers must be able to:

- Access only manuscripts assigned to them.
- Read the manuscript and relevant supplementary materials.
- Add comments and annotations.
- Submit confidential reviewer reports.
- Recommend a decision using the journal's configured options.
- Save drafts of their reviews.
- Submit their final review.

Reviewers must not be able to publish manuscripts, change editorial decisions, access unrelated submissions, or see confidential information belonging to other reviewers unless the journal's policy explicitly permits it.

## 3.3 Editor permissions

Editors must be able to:

- View manuscripts assigned to them.
- Inspect reviewer recommendations.
- Add editorial comments.
- Request revisions.
- Communicate editorial decisions through the journal system.
- Manage the manuscript's progress.
- Edit the manuscript only where the workflow authorizes it.
- Compare versions and inspect the audit history.

Editors must not silently overwrite the original submission or modify a reviewer's submitted report.

## 3.4 Managing Editor permissions

Provide appropriate controls for:

- Coordinating manuscript assignments.
- Monitoring editorial deadlines.
- Managing revision rounds.
- Tracking reviewer invitations and responses.
- Monitoring manuscripts awaiting decisions.
- Coordinating copyediting and proof approval.
- Identifying delayed manuscripts.
- Viewing workflow reports.

The Managing Editor role must not automatically inherit unrestricted Super Admin privileges.

## 3.5 Super Admin permissions

Preserve the existing administrative system and provide appropriately protected configuration controls for:

- Role and permission management.
- Journal formatting profiles.
- Editorial workflow settings.
- Document-processing settings.
- Retention policies and system configuration.
- Audit and operational reports.

## 3.6 Security requirements

Implement and test:

- Server-side authorization policies.
- Private document storage.
- Secure file delivery.
- Protection against insecure direct object references.
- CSRF protection and input validation.
- Appropriate XSS prevention for manuscript content and comments.
- Rate limiting where necessary.
- Secure session and authentication handling.
- Auditing of sensitive document access and changes.

For anonymous or double-anonymous peer review, prevent unintended disclosure of author and reviewer identities through the interface, document metadata, file names, comments, notifications, and downloadable documents where applicable.

Do not assume that hiding a name in the interface makes a document anonymous.

## 3.7 Module 3 acceptance criteria

Test each role using actual authorization checks and representative accounts. Demonstrate both permitted and forbidden actions.
